# PRD 1단계: 냉장고 사진 재료 인식

## 1. 개요

사용자가 냉장고 사진을 올리면 사진 속 식재료 목록을 만들어 보여 준다. 이 목록은 2단계(레시피 생성)의 입력이 된다.

- 사용 모델: `nvidia/nemotron-3.5-embed-1b:free` (OpenRouter)
- 전체 서비스: 1단계 재료 인식 → 2단계 레시피 생성(`PRD_step2.md`) → 3단계 프로필·레시피 저장(`PRD_step3.md`)

## 2. 모델 특성과 인식 방식 (핵심 제약)

이 모델은 **임베딩 모델**이다. 이미지를 설명하는 문장을 만들어 주지 않고, 이미지와 텍스트를 각각 2048차원 벡터로 바꿔 줄 뿐이다(OpenRouter 표기: `text+image->embeddings`). 따라서 "사진에 무엇이 있는지"를 모델에게 직접 물을 수 없다.

인식은 **후보 재료 목록과의 유사도 비교(제로샷 분류)**로 한다.

1. 미리 정해 둔 후보 재료 목록(예: 달걀, 우유, 양파, 두부 …)의 문장을 텍스트 임베딩으로 만들어 둔다.
2. 업로드된 사진을 이미지 임베딩으로 만든다.
3. 사진 벡터와 각 재료 벡터의 코사인 유사도를 계산해, 점수가 높은 재료를 "인식된 재료"로 판정한다.

사전 테스트 결과(2026-10-26, 흰 배경 위 빨간 원 이미지):

| 후보 문장 | 유사도 |
|---|---|
| a red circle on a white background (정답) | 0.4511 |
| 흰 배경 위의 빨간 원 (정답, 한국어) | 0.3684 |
| a green triangle on a black background | 0.2082 |
| a blue square on a white background | 0.1802 |
| a photo of a cat | 0.1756 |

→ 정답이 확실히 높게 나오지만 절대값은 0.4 수준이다. 고정 임계값 대신 **상대 순위 + 보정된 임계값**을 써야 한다. 영어 문장이 한국어보다 점수가 높았으므로, 비교용 문장은 영어로 만들고 화면에는 한국어 이름을 보여 준다.

### 여러 재료가 섞인 사진 처리

냉장고 사진 한 장을 통째로 임베딩하면 여러 재료의 특징이 하나의 벡터에 섞여 개별 재료 점수가 낮아진다. 이를 줄이기 위해 다음을 함께 쓴다.

- **타일 분할:** 원본 전체 + 겹치는 격자 조각(예: 3×3)을 각각 임베딩하고, 재료별로 조각들 중 최고 점수를 그 재료의 점수로 쓴다.
- **사용자 확인 단계:** 인식 결과는 "추정"으로 보여 주고, 사용자가 재료를 빼거나 직접 추가한 뒤 확정한다. 인식이 완벽하지 않다는 것을 전제로 한 설계다.

## 3. 목표 / 비목표

**목표**
- 사진 1장에서 후보 목록 안의 주요 재료를 추정해 점수와 함께 보여 준다.
- 사용자가 결과를 수정·확정할 수 있다.
- API 키가 브라우저에 노출되지 않는다.

**비목표**
- 후보 목록에 없는 재료 인식 (모델 구조상 불가능)
- 수량·유통기한·신선도 판별
- 재료 위치(바운딩 박스) 표시

## 4. 사용자 흐름

1. 사용자가 사진을 고른다(파일 선택 또는 드래그 앤 드롭, 모바일은 카메라 촬영).
2. 미리보기가 뜨고 "재료 인식" 버튼을 누른다.
3. 로딩 표시 후 인식된 재료가 칩(chip) 목록으로 나온다. 각 칩에 신뢰도(높음/보통)를 표시한다.
4. 사용자가 칩을 지우거나, 검색창에서 후보 목록의 재료를 직접 추가한다.
5. "재료 확정"을 누르면 확정 목록이 2단계로 넘어간다.

## 5. 기능 요구사항

| ID | 요구사항 |
|---|---|
| F1-1 | JPEG/PNG/WebP 이미지를 받는다. 최대 10MB. |
| F1-2 | 브라우저에서 긴 변 1024px로 줄이고 JPEG로 다시 압축한 뒤 base64 data URL로 서버에 보낸다(업로드 용량·토큰 절감). |
| F1-3 | 서버는 원본 + 3×3 격자 조각(조각 간 20% 겹침)을 이미지 임베딩으로 만든다. |
| F1-4 | 후보 재료 목록은 `data/ingredients.json`에 둔다. 항목 형식: `{ "id": "egg", "ko": "달걀", "prompt": "a photo of eggs" }`. 초기 목록은 한국 가정 냉장고 기준 약 80개. 프롬프트에 "in a refrigerator"를 붙이면 정확도가 떨어진다(10장 평가 결과 참고). |
| F1-5 | 재료 텍스트 임베딩은 서버 시작 시 한 번 만들어 `data/ingredient-embeddings.json`에 캐시한다. 목록 내용이 바뀌면(해시 비교) 다시 만든다. |
| F1-6 | 재료 점수 = 모든 조각 중 최고 코사인 유사도. 점수 ≥ 하한 `T`이면서 상위 `K`개 안에 드는 재료를 결과로 낸다. 기본값 `T=0.30`, `K=5`. 실제 사진에서는 모든 재료가 0.4~0.6에 몰리므로 `T`는 비식품 이미지를 거르는 하한 역할만 한다. |
| F1-7 | 신뢰도 표시: 그 사진의 1위 점수와 0.02 이내면 "높음", 그 외는 "보통". |
| F1-8 | 사용자가 결과 칩을 삭제하고, 후보 목록 자동완성으로 재료를 추가할 수 있다. |
| F1-9 | 확정된 재료 목록(한국어 이름 배열)을 2단계 입력으로 넘긴다. |

## 6. 시스템 구성

```
브라우저 (HTML/CSS/JS, 빌드 도구 없음)
   │  POST /api/recognize  { image: "data:image/jpeg;base64,..." }
   ▼
로컬 Node.js 서버 (Node 24, Express)
   │  .env에서 OPENROUTER_API_KEY 읽기 (process.loadEnvFile)
   │  이미지 분할 → 임베딩 요청 → 유사도 계산
   ▼
OpenRouter  POST https://openrouter.ai/api/v1/embeddings
```

- 서버는 정적 파일(`public/`)과 API를 함께 제공한다.
- 이미지 분할은 서버에서 `sharp`로 처리한다.

### OpenRouter 요청 형식 (테스트로 확인됨)

```json
// 이미지 임베딩
{ "model": "nvidia/nemotron-3.5-embed-1b:free",
  "input": [ { "content": [ { "type": "image_url", "image_url": { "url": "data:image/png;base64,..." } } ] } ] }

// 텍스트 임베딩 (여러 개를 한 번에)
{ "model": "nvidia/nemotron-3.5-embed-1b:free",
  "input": ["a photo of eggs in a refrigerator", "a photo of milk in a refrigerator"] }
```

응답의 `data[i].embedding`이 2048차원 벡터다. 조각 10개를 하나의 `input` 배열로 묶어 한 번에 보낼 수 있는지는 구현 초기에 확인하고, 안 되면 동시 요청 수를 3개로 제한해 나눠 보낸다.

## 7. API 명세

`POST /api/recognize`

요청:
```json
{ "image": "data:image/jpeg;base64,..." }
```

응답 200:
```json
{
  "ingredients": [
    { "id": "egg", "name": "달걀", "score": 0.41, "confidence": "high" },
    { "id": "onion", "name": "양파", "score": 0.33, "confidence": "normal" }
  ],
  "elapsedMs": 4200
}
```

오류 응답: `{ "error": { "code": "...", "message": "사용자에게 보여 줄 한국어 메시지" } }`

| code | 상황 |
|---|---|
| `INVALID_IMAGE` | 형식·크기 위반 |
| `RATE_LIMITED` | OpenRouter 429가 재시도 후에도 계속됨 |
| `UPSTREAM_ERROR` | 그 밖의 OpenRouter 오류 |

## 8. 비기능 요구사항

- **보안:** API 키는 서버에서만 읽는다. 브라우저 코드, 응답, 로그에 키를 남기지 않는다.
- **무료 모델 한도:** 무료 모델은 공유 한도 때문에 429가 자주 난다(사전 테스트에서 Gemma 계열은 수 분간 계속 429). 429·502일 때 지수 백오프(2s, 4s, 8s, 최대 3회)로 재시도하고, 그래도 실패하면 "잠시 후 다시 시도" 안내를 띄운다.
- **응답 시간:** 목표 10초 이내 (임베딩 1회 약 0.8초 × 조각 10개, 병렬 처리 기준).
- **개인정보:** 업로드 이미지는 서버에 저장하지 않고 요청이 끝나면 버린다.

## 9. 수용 기준

- [ ] 사진을 올리면 10초 안에 재료 칩 목록이 나온다.
- [ ] 테스트 사진 10장(재료가 정답으로 표시된 사진)에서 상위 결과의 정밀도 ≥ 60%, 재현율 ≥ 50%. (미달: 10장 참고)
- [ ] 사용자가 재료를 삭제·추가하고 확정할 수 있다.
- [ ] 개발자 도구 네트워크 탭과 페이지 소스에 API 키가 보이지 않는다.
- [ ] OpenRouter가 429를 돌려주면 재시도하고, 끝내 실패하면 오류 안내가 뜬다(화면이 멈추지 않음).

## 10. 구현 후 평가 결과 (2026-10-26)

공개 냉장고 사진 11장(Wikimedia Commons, 미국 농무부 공공 저작물)에 정답 재료를 직접 표시하고 `npm run evaluate`로 측정했다.

| 방식 | 정밀도 | 재현율 | 정답 재료 평균 순위 (80개 중) |
|---|---|---|---|
| 최초 설계: 프롬프트 "... in a refrigerator", 임계값 0.30, 상위 15개 | 12% | 35% | 27.2 |
| 프롬프트 "a photo of ...", 상위 3개 | 39% | 23% | 27.5 |
| **현재 기본값:** 프롬프트 "a photo of ...", 상위 5개 | 27% | 26% | 27.5 |
| 위 + 재료별 편향 보정 | 24% | 23% | 31.7 |

- **수용 기준(정밀도 ≥ 60%, 재현율 ≥ 50%)을 충족하지 못했다.** 정답 재료의 평균 순위가 80개 중 27위 정도로, 무작위(약 40위)보다 조금 나은 수준이다.
- 단일 대상 이미지(예: 과일만 담긴 칸)는 잘 맞히지만, 여러 재료가 섞인 일반 냉장고 사진에서는 약하다. 모델 설명대로 문서 페이지 검색용으로 학습된 모델이라 자연 사진의 개별 물체 인식에 맞지 않는 것으로 보인다.
- 5×5 격자 분할은 무료 하루 요청 한도에 걸려 측정하지 못했다.
- 대안: 2단계 모델 `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`는 이미지 입력을 받는 대화형 모델이다. 사진을 주고 재료 목록을 JSON으로 답하게 하는 방식을 같은 평가 세트로 비교해 볼 가치가 있다.

## 11. 리스크

| 리스크 | 대응 |
|---|---|
| 임베딩 모델이 여러 재료가 섞인 사진에 약함 | 타일 분할 + 사용자 확인 단계. 정확도가 부족하면 이미지 설명이 가능한 비전 대화 모델(예: `google/gemma-4-26b-a4b-it:free`)로 바꾸는 방안을 검토한다. 단, 이 모델들은 테스트 시점에 429가 계속 났다. |
| 후보 목록 밖 재료는 인식 불가 | 사용자 직접 추가 기능, 목록 확장 |
| 임계값이 사진마다 다르게 맞음 | 설정값으로 분리하고 실제 사진으로 보정 |
| 무료 모델 서비스 중단·변경 | 모델 ID를 설정값으로 분리 |
