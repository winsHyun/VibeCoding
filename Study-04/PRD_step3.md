# PRD 3단계: 사용자 프로필과 레시피 저장

## 1. 개요

사용자 프로필을 만들어 식단 정보(알레르기, 식단 제한, 선호)를 저장하고, 마음에 드는 레시피를 프로필에 저장해 다시 볼 수 있게 한다. 프로필 정보는 2단계 레시피 생성 프롬프트에 반영된다.

- 선행 단계: `PRD_step1.md`(재료 인식), `PRD_step2.md`(레시피 생성)
- 새 AI 모델 호출 없음. 서버 저장 기능과 2단계 프롬프트 연동이 핵심이다.

## 2. 목표 / 비목표

**목표**
- 프로필을 만들고, 고르고, 고치고, 지울 수 있다.
- 2단계 레시피를 현재 프로필에 저장하고, 목록·상세 보기·삭제를 할 수 있다.
- 프로필의 알레르기와 식단 제한이 레시피 추천에 반영된다.

**비목표**
- 회원가입, 비밀번호 로그인, 소셜 로그인 (로컬 개인용 앱으로 한정)
- 여러 기기 간 동기화, 레시피 공유
- 장보기 목록, 냉장고 재고 관리

## 3. 사용 환경 가정

로컬 PC에서 서버를 띄워 가족이나 개인이 쓰는 앱이다. 그래서 인증 없이 "프로필 선택" 방식으로 쓴다(넷플릭스 프로필 선택과 비슷함). 외부에 공개 배포하려면 인증이 필요하며, 그건 이번 범위 밖이다.

## 4. 사용자 흐름

1. 처음 접속하면 "프로필 만들기" 화면이 나온다. 프로필이 있으면 프로필 선택 화면이 나온다.
2. 프로필을 만들 때 이름(필수)과 식단 정보(선택)를 입력한다.
3. 선택한 프로필은 브라우저에 기억해 두고(`localStorage`의 프로필 ID), 다음 접속 때 자동으로 선택한다. 헤더에서 언제든 바꿀 수 있다.
4. 2단계 레시피 카드의 "저장" 버튼을 누르면 현재 프로필에 저장된다. 이미 저장한 레시피면 "저장됨"으로 표시된다.
5. "내 레시피" 화면에서 저장한 레시피를 최신순으로 보고, 상세 보기·메모 추가·삭제를 한다.

## 5. 기능 요구사항

**프로필**

| ID | 요구사항 |
|---|---|
| F3-1 | 프로필 필드: 이름(1~20자, 중복 불가), 알레르기(다중 선택 + 직접 입력), 식단 제한(채식/비건/저염/저탄수 등 다중 선택), 선호 요리(한식/양식/중식/일식 등), 매운맛 선호(0~3), 기본 인분(1~4). |
| F3-2 | 프로필 생성·조회·수정·삭제. 삭제하면 그 프로필의 저장 레시피도 함께 삭제하며, 삭제 전에 확인창을 띄운다. |
| F3-3 | 프로필은 최대 10개까지 만들 수 있다. |

**레시피 저장**

| ID | 요구사항 |
|---|---|
| F3-4 | 2단계 레시피 객체 전체를 저장한다. 함께 저장하는 것: 저장 시각, 생성에 쓴 재료 목록, 사용자 메모(최대 500자). |
| F3-5 | 같은 프로필에서 같은 제목+같은 재료 구성의 레시피는 중복 저장하지 않는다. |
| F3-6 | 저장 레시피 목록: 최신순 정렬, 제목 검색. |
| F3-7 | 저장 레시피 상세 보기, 메모 수정, 삭제. |

**2단계 연동**

| ID | 요구사항 |
|---|---|
| F3-8 | `POST /api/recipes` 요청에 `profileId`를 받는다. 서버가 프로필을 읽어 알레르기·식단 제한·선호·매운맛을 프롬프트에 넣는다. |
| F3-9 | 레시피 생성 후, 알레르기 재료가 레시피 재료에 들어 있으면 해당 레시피에 `allergyWarning` 배열을 붙인다. 화면에는 경고 배지를 띄운다. |
| F3-10 | 레시피 화면의 인분 기본값은 프로필의 기본 인분으로 채운다. |

## 6. 데이터 저장

서버의 JSON 파일에 저장한다. 데이터베이스는 이번 범위에서 쓰지 않는다.

- 위치: `data/user/db.json`. 1단계의 `data/ingredients.json`은 커밋해야 하므로 사용자 데이터만 `data/user/`로 분리하고, `.gitignore`에는 `data/user/`만 추가한다.
- 동시 쓰기로 파일이 깨지지 않게, 쓰기는 서버 안에서 하나씩 순서대로 처리하고 임시 파일에 쓴 뒤 이름을 바꾸는 방식으로 저장한다.

```json
{
  "profiles": [
    {
      "id": "p_8f3k2a",
      "name": "엄마",
      "allergies": ["땅콩", "새우"],
      "dietaryRestrictions": ["저염"],
      "preferredCuisines": ["한식"],
      "spiceLevel": 1,
      "defaultServings": 3,
      "createdAt": "2026-10-26T14:33:00+09:00",
      "updatedAt": "2026-10-26T14:33:00+09:00"
    }
  ],
  "savedRecipes": [
    {
      "id": "r_x91mz0",
      "profileId": "p_8f3k2a",
      "recipe": { "title": "달걀 양파 볶음밥", "...": "2단계 레시피 구조 그대로" },
      "sourceIngredients": ["달걀", "양파"],
      "memo": "",
      "savedAt": "2026-10-26T15:00:00+09:00"
    }
  ]
}
```

- ID는 `crypto.randomUUID()`로 만든다(위 예시는 짧게 줄인 것).

## 7. API 명세

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/profiles` | 프로필 목록 |
| POST | `/api/profiles` | 프로필 생성 |
| GET | `/api/profiles/:id` | 프로필 조회 |
| PUT | `/api/profiles/:id` | 프로필 수정 |
| DELETE | `/api/profiles/:id` | 프로필과 저장 레시피 삭제 |
| GET | `/api/profiles/:id/recipes?q=` | 저장 레시피 목록 (제목 검색) |
| POST | `/api/profiles/:id/recipes` | 레시피 저장 (중복이면 409와 기존 ID 반환) |
| PATCH | `/api/profiles/:id/recipes/:recipeId` | 메모 수정 |
| DELETE | `/api/profiles/:id/recipes/:recipeId` | 레시피 삭제 |

오류 형식은 1·2단계와 같다. 추가 코드: `NOT_FOUND`, `DUPLICATE`, `VALIDATION_ERROR`, `LIMIT_EXCEEDED`.

## 8. 화면 구성

- **프로필 선택/생성 화면:** 프로필 카드 목록 + "새 프로필" 버튼
- **프로필 편집 화면:** F3-1 필드 입력 폼
- **헤더:** 현재 프로필 이름, 프로필 바꾸기, "내 레시피" 링크
- **내 레시피 화면:** 검색창 + 레시피 카드 목록, 카드를 누르면 상세(2단계 카드와 같은 형식 + 메모 칸)

## 9. 수용 기준

- [ ] 프로필을 만들고 서버를 재시작해도 프로필과 저장 레시피가 그대로 남아 있다.
- [ ] 브라우저를 다시 열면 마지막에 고른 프로필이 자동 선택된다.
- [ ] 알레르기로 "새우"를 등록한 프로필로 추천받으면 레시피에 새우가 없거나, 있으면 경고 배지가 붙는다.
- [ ] 같은 레시피를 두 번 저장하면 "이미 저장된 레시피" 안내가 뜨고 중복 저장되지 않는다.
- [ ] 프로필을 삭제하면 해당 저장 레시피도 사라진다.
- [ ] `git status`에 `data/user/` 아래 파일이 나타나지 않는다.

## 10. 구현 상태 (2026-10-26)

- 구현: `src/store.js`(JSON 파일 저장소), `src/profiles.js`(프로필·저장 레시피 로직, 알레르기 키워드), 7장의 API 전부와 `GET /api/profile-options`, 프로필 선택·편집·내 레시피 화면(`public/js/profile.js`, `saved.js`).
- 알레르기 검사(F3-9)는 항목별 키워드로 넓게 잡는다. 예: 대두 → 두부·간장·된장, 우유 → 치즈·버터, 새우 → 새우젓. 직접 입력한 알레르기는 이름 그대로 비교한다.
- 저장한 레시피에도 알레르기 경고를 함께 저장한다. 프로필의 알레르기를 나중에 바꿔도 이미 저장한 레시피의 경고는 다시 계산하지 않는다.
- 검증:
  - `npm test`: 이 단계 12개 포함 29개 통과.
  - 실제 HTTP API 점검: 서버 재시작 후 데이터 유지, 중복 저장 409, 함께 삭제 등 수용 기준 확인.
  - 헤드리스 Edge로 화면 흐름 19개 항목 확인.
- 9장 수용 기준 중 "알레르기 프로필로 추천받으면 경고"는 서버 후처리 로직이라 데모 모드에서 확인했다. 실제 모델이 프롬프트의 알레르기 조건을 지키는지는 OpenRouter 하루 한도 소진으로 아직 확인하지 못했다.

## 11. 리스크

| 리스크 | 대응 |
|---|---|
| 인증이 없어 같은 PC의 누구나 모든 프로필을 볼 수 있음 | 로컬 개인용으로 범위를 한정하고 화면에 명시. 외부 배포 시 인증을 별도 단계로 추가 |
| JSON 파일 저장 중 서버가 꺼지면 파일 손상 | 임시 파일에 쓴 뒤 이름 바꾸기 방식으로 저장 |
| 모델이 알레르기 조건을 무시함 | 서버 후처리 검사(F3-9)로 경고 |
| 데이터가 커지면 JSON 파일이 느려짐 | 프로필 10개 제한. 규모가 커지면 SQLite로 옮김 |
