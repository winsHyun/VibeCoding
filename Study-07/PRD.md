# PRD: 대전 빵지순례 (빵집 정보 · 추천 코스 · 실시간 현장 상황)

## 1. 배경과 목표

대전은 성심당을 중심으로 "빵지순례" 여행지로 알려져 있지만, 방문자가 가장 궁금한 정보는 **"지금 가면 줄이 얼마나 긴가, 원하는 빵이 남아 있나"** 입니다. 이 정보는 공식 채널에 없고, SNS 글은 시간이 지나 믿기 어렵습니다.

이 서비스는 두 가지를 제공합니다.

1. **정적 정보**: 대전 주요 빵집의 기본 정보(위치·대표 메뉴·운영 시간)와 동선을 고려한 **추천 코스**.
2. **현장 상황 공유**: 빵집 앞에 있는 사람이 줄 길이·대기 시간·품절 여부를 **현장에서 등록**하면, 다른 곳에 있는 사람이 **실시간으로** 확인하고 링크로 **공유**할 수 있습니다.

### 목표
- 빵집 목록·상세·추천 코스를 모바일에서 3번 탭 안에 찾아볼 수 있다.
- 현장 사용자가 **10초 안에** 상황을 등록할 수 있다(탭 몇 번 + 선택 메모).
- 다른 사용자는 각 빵집의 **최신 상황과 등록 시각("12분 전")** 을 새로고침 없이 본다.
- 오래된 정보·거짓 정보가 사용자를 오도하지 않도록 **만료·현장 인증·신고** 장치를 둔다.

### 비목표 (1차 범위 밖)
- 주문·예약·결제, 빵집 사장님용 관리 화면
- 회원가입·로그인(이메일/소셜). 1차는 익명 사용
- 리뷰·별점, 댓글·채팅
- 대전 외 지역

## 2. 대상 사용자와 사용 시나리오

| 사용자 | 상황 | 원하는 것 |
|---|---|---|
| 당일치기 여행자 | KTX로 대전역 도착, 반나절 일정 | 동선 좋은 코스, 지금 줄 짧은 곳 |
| 대전 시민 | 퇴근길에 들를지 고민 | 지금 원하는 빵이 남았는지 |
| 현장 방문자 | 빵집 앞에서 줄 서는 중 | 상황을 빠르게 올려 다른 사람을 돕기 |
| 일행 | 따로 이동 중 | 카톡으로 받은 링크로 같은 상황 보기 |

**시나리오 A — 코스 따라가기**: 홈 → [추천 코스] → "대전역 출발 원도심 코스" → 순서대로 빵집 카드(이동 시간, 대표 메뉴, **현재 상황 배지**) → 카드에서 지도 앱 길찾기.

**시나리오 B — 현장 등록**: 빵집 상세 → [지금 상황 알리기] → 위치 권한 허용 → 대기 수준 선택(없음/짧음/보통/김) → 품절 빵 태그 선택(선택) → 메모(선택) → [등록]. 등록 즉시 다른 사용자 화면에 나타남.

**시나리오 C — 공유**: 빵집 상세 → [공유] → 휴대폰 공유 시트(카카오톡 등) 또는 링크 복사. 받은 사람은 링크로 그 빵집 상세와 최신 상황을 바로 봄.

## 3. 기능 요구사항

### 3.1 빵집 정보 (F-1 ~ F-4)

- **F-1 빵집 목록**: 카드 목록(이름, 지역, 대표 메뉴 1~2개, 현재 상황 배지). 지역(원도심/둔산/유성·도룡 등) 필터, 이름 검색.
- **F-2 빵집 상세**: 이름, 주소, 운영 시간·휴무일, 대표 메뉴, 한 줄 소개, 팁(예: "튀김소보로는 오전에 줄이 짧음"), 지도 앱 링크(카카오맵/네이버지도 길찾기), **현재 상황 영역**(3.3).
- **F-3 지도 보기**: 빵집을 지도 위 마커로 표시, 마커 색은 현재 대기 수준. (지도 공급자는 7장 열린 질문)
- **F-4 데이터 관리**: 빵집·코스 데이터는 DB에 두고, 1차는 관리자 화면 없이 SQL 시드/마이그레이션으로 관리. **주소·운영 시간은 등록 전 공식 출처(매장 공지·지도 앱)로 확인**하고 `verified_at`(확인 날짜)을 함께 저장해 상세 화면에 "정보 확인일"로 표시.

초기 수록 후보(확정 전 조사 필요): 성심당 본점·케익부띠끄·대전역점·DCC점·롯데백화점 대전점 등 성심당 계열, 그 밖에 지역별로 많이 언급되는 빵집 10~15곳. 최종 목록은 M1 시작 전에 확정.

### 3.2 추천 코스 (F-5 ~ F-6)

- **F-5 코스 목록**: 코스 이름, 소요 시간, 이동 수단(도보/대중교통/차), 빵집 수, 출발 지점.
  - 예시: "대전역 출발 원도심 도보 코스(2~3시간)", "성심당 집중 코스", "둔산·유성 차량 코스", "오전 줄 피하기 코스".
- **F-6 코스 상세**: 순서가 있는 빵집 목록, 구간별 예상 이동 시간, 코스 팁, 각 빵집의 **현재 상황 배지**. 각 빵집 카드에서 상세로 이동. 코스 상단에 "이 코스 공유" 버튼.

### 3.3 실시간 현장 상황 (F-7 ~ F-12) — 핵심 기능

- **F-7 상황 등록 항목**

  | 항목 | 필수 | 값 |
  |---|:-:|---|
  | 대기 수준 | ✅ | `none` 바로 입장 / `short` ~10분 / `medium` 10~30분 / `long` 30분 이상 |
  | 줄 선 사람 수(대략) | | 숫자 0~300 |
  | 품절 메뉴 | | 그 빵집 대표 메뉴 태그에서 선택(여러 개) |
  | 메모 | | 140자, 링크 금지 |
  | 사진 | | 2차(M4)에서 검토 |

- **F-8 현장 인증**: 등록할 때 브라우저 위치(Geolocation)를 받아 빵집 좌표와의 거리가 **300m 이내**여야 등록 가능. 위치 권한을 거부하면 등록 불가 안내. 거리 판정은 서버(DB 함수)에서 하고, **원본 좌표는 저장하지 않고** 판정 결과만 남깁니다(개인정보 최소화). ※ 위치는 조작 가능하므로 완전한 방어가 아니며 F-11·F-12와 함께 씁니다.
- **F-9 표시 규칙**
  - 빵집별로 **최신 등록 1건**을 크게(대기 수준 배지 + "12분 전" + 메모), 최근 60분 등록 목록을 아래에 작게.
  - 최근 60분 안에 여러 건이면 "최근 n건 중 다수: 보통" 처럼 요약.
  - **만료**: 90분이 지난 등록은 "최근 정보 없음"으로 표시하고 배지에 쓰지 않음(목록에서는 흐리게 24시간까지 보존 후 숨김).
  - 운영 시간 밖에는 "영업 종료" 를 우선 표시.
- **F-10 실시간 갱신**: 화면을 연 상태에서 새 등록이 생기면 새로고침 없이 반영(Supabase Realtime). 상대 시각("12분 전")은 1분마다 갱신. 연결이 끊기면 "실시간 연결 끊김 · 다시 연결 중" 표시.
- **F-11 도배 방지**: 같은 사용자(익명 세션)는 같은 빵집에 **10분에 1건**, 전체 **1시간에 10건**까지. 메모는 길이·금지어·URL 검사.
- **F-12 신고**: 각 등록에 [신고] 버튼(사유: 거짓 정보/부적절한 내용/광고). 서로 다른 사용자 **3명**이 신고하면 자동으로 숨김. 같은 사용자는 한 등록을 한 번만 신고.

### 3.4 공유 (F-13 ~ F-14)

- **F-13 링크**: 빵집 상세(`?bakery=<slug>`)와 코스 상세(`?course=<slug>`)는 고유 주소를 가지며, 링크로 열면 그 화면이 바로 열림.
- **F-14 공유 버튼**: Web Share API(모바일 공유 시트)를 쓰고, 지원하지 않으면 링크 복사 + "복사했어요" 알림. 공유 문구 예: "성심당 본점 지금 대기 짧음(~10분) · 5분 전 제보 · <링크>".
- (2차) 카카오톡 공유 SDK, 빵집별 미리보기 이미지(OG 태그).

## 4. 비기능 요구사항

- **모바일 우선**: 폭 360px 기준 설계, 한 손 조작. 현장 등록 버튼은 화면 하단 고정.
- **성능**: 첫 화면 3초 이내(4G 기준), 등록 후 다른 화면 반영 3초 이내.
- **보안**
  - Supabase RLS로 테이블 직접 쓰기를 막고, 등록·신고는 **DB 함수(RPC)** 로만 허용(거리·도배 검사를 함수 안에서 수행).
  - 사용자 식별은 Supabase **익명 로그인**(anonymous sign-in) 세션 id. 개인정보(이름·연락처·좌표)는 저장하지 않음.
  - 메모는 화면에 `textContent`로만 넣어 XSS 방지.
- **접근성**: 대기 수준은 색만이 아니라 글자로도 표시, 버튼에 레이블.
- **신뢰 표시**: 모든 상황 정보 옆에 "이용자 제보이며 실제와 다를 수 있어요" 안내.

## 5. 기술 구성 (제안)

Study-06과 같은 구성을 이어 씁니다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 화면 | 빌드 도구 없는 HTML/CSS/JS (ES Modules) | 기존 실습과 동일, Vercel 정적 배포 |
| DB·API | Supabase (PostgreSQL, RLS, RPC 함수) | 서버 코드 없이 검증 로직을 DB 함수에 둠 |
| 실시간 | Supabase Realtime (`reports` 테이블 INSERT 구독) | 별도 서버 불필요 |
| 사용자 | Supabase 익명 로그인 | 가입 없이 도배 방지·신고 중복 방지 |
| 배포 | Vercel | Study-06과 동일 |
| 지도 | 카카오맵 JS SDK (열린 질문) | 국내 장소 정확도 |

### 5.1 데이터 모델 (초안)

- `bakeries`: `id`, `slug`, `name`, `area`, `address`, `lat`, `lng`, `hours`(JSON: 요일별), `closed_days`, `signature_menus`(text[]), `description`, `tips`, `map_url`, `verified_at`
- `courses`: `id`, `slug`, `title`, `summary`, `duration_min`, `transport`, `start_point`, `tips`
- `course_stops`: `course_id`, `seq`, `bakery_id`, `move_min`(이전 지점에서 이동 시간), `note`
- `reports`: `id`, `bakery_id`, `user_id`(익명 세션), `wait_level`, `queue_count`, `sold_out`(text[]), `memo`, `distance_m`, `hidden`(bool), `created_at`
- `report_flags`: `report_id`, `user_id`, `reason`, `created_at` (PK: report_id + user_id)

### 5.2 DB 함수 (RPC)

- `submit_report(bakery_id, wait_level, queue_count, sold_out, memo, lat, lng)` → 거리 300m 검사, 도배 제한 검사, 입력 검증 후 INSERT. 좌표는 거리 계산에만 쓰고 저장하지 않음. 실패 시 오류 코드: `TOO_FAR`, `RATE_LIMITED`, `INVALID_INPUT`, `NOT_FOUND`.
- `flag_report(report_id, reason)` → 중복 신고 무시, 신고 3건이면 `hidden = true`. 자기 등록은 신고 불가.
- 읽기: `reports`는 `hidden = false`이고 24시간 이내인 행만 `select` 허용(RLS).

## 6. 완료 기준

- [ ] 빵집 목록·검색·지역 필터, 상세, 코스 목록·상세가 동작하고 모든 빵집에 `verified_at`이 있다.
- [ ] 300m 안에서는 등록되고, 밖에서는 `TOO_FAR` 안내가 나온다.
- [ ] 두 브라우저를 열어 한쪽에서 등록하면 다른 쪽에 3초 안에 반영된다.
- [ ] 90분 지난 등록은 배지에서 빠지고 "최근 정보 없음"이 나온다.
- [ ] 10분 안에 같은 빵집 두 번째 등록은 `RATE_LIMITED`로 막힌다.
- [ ] 서로 다른 3명이 신고하면 등록이 숨겨진다.
- [ ] 빵집·코스 링크를 새 창으로 열면 해당 화면이 바로 열리고, 공유 버튼이 모바일·PC에서 동작한다.
- [ ] Supabase advisor 보안 경고(RLS 누락 등)가 없다.
- [ ] Vercel 배포 주소에서 위 항목이 동작한다.

### M2·M3 구현 메모 (2026-11-03)
- 사용자 구분은 Supabase 익명 로그인 대신 기기 ID + IP 해시로 함(Auth 설정 없이 동작). 제보 등록·실시간 반영·신고 3건 자동 숨김·지도 실시간 필터 구현.
- 추가: "요즘 핫한 빵집"(최근 7일 상세 조회 수 + 제보 수×3), 첫 화면 "지금 현장 소식"(최근 90분 제보).
- 남은 것: 운영 시간 밖 "영업 종료" 표시(영업시간이 글로만 있어 보류), 사진 제보(M4).

### M2. 현장 상황 등록·표시 (의존: M1)
- 익명 로그인, `reports` 테이블, `submit_report` RPC(거리·도배·입력 검사).
- 화면: 등록 시트, 최신 상황 영역, 목록·코스 카드의 상황 배지, 만료 규칙.

### M3. 실시간·공유·신고 (의존: M2)
- Realtime 구독, 상대 시각 갱신, 연결 끊김 표시.
- 공유 버튼(Web Share / 링크 복사), `report_flags` + `flag_report` RPC.
- 지도 보기(F-3, 열린 질문 1 결정 후).

### M4. (선택) 사진·카카오 공유
- 사진 업로드, 카카오톡 공유, OG 미리보기.
