## 4. 버그

### B-01 하루 무료 한도 소진 시 화면이 "잠시 후 다시"와 재시도 버튼을 보여 줌
- **심각도**: 보통
- **위치**: `index.html:713-714` (`describeError`의 `RATE_LIMITED`)
- **재현**: 가짜 OpenRouter가 `429 "Rate limit exceeded: free-models-per-day"`를 주게 한 뒤 화면에서 일기 제출.
- **기대**: 서버가 보낸 "오늘 사용할 수 있는 무료 AI 요청을 모두 썼어요. 내일 다시 시도해 주세요."를 보여 주고, 재시도 버튼은 숨김.
- **실제**: 서버 응답은 맞음 — `{"error":{"code":"RATE_LIMITED","message":"오늘 사용할 수 있는 무료 AI 요청을 모두 썼어요. 내일 다시 시도해 주세요."}}`. 그런데 화면은 `잠깐 쉬었다가 다시 전해 주세요 / 지금 일기 친구에게 이야기가 많이 몰려 있어요. 잠시 후 다시 시도해 주세요. … / 다시 전하기`. 사용자가 재시도할 때마다 실패 요청도 한도에 들어감.
- **관련**: R6, R4(한도 정책)
- **수정 방향**: 서버 `message`를 그대로 쓰거나, 서버가 `error.retryable:false`·별도 코드(예: `DAILY_LIMIT`)를 주게 하고 화면에서 재시도 버튼을 숨김.

### B-02 다른 출처 웹페이지가 일기 목록을 읽고 지울 수 있음 (`Origin: null` 허용 + Host 검사 없음)
- **심각도**: 높음 (보안·개인 일기 노출)
- **위치**: `src/cors.js:4-5` (`origin === "null"` 허용), `src/app.js` 전체(Host 헤더 검사 없음)
- **재현 1 (sandbox iframe)**: `http://127.0.0.2:8081`에서 다음 페이지를 열면(허용 목록 밖 출처)
  ```html
  <iframe sandbox="allow-scripts" srcdoc="<script>fetch('http://127.0.0.1:3000/api/entries').then(r=>r.json()).then(d=>parent.postMessage('READ '+d.entries.length+' entries, first: '+d.entries[0].text,'*'))</script>"></iframe>
  ```
  결과: `origin: http://127.0.0.2:8081 => READ 15 entries, first: 아플 때 친구가 말없이 죽을 사다 줘서 정말 고마웠어`. sandbox iframe의 Origin은 `null`이라 file://와 구분되지 않음. 같은 방식으로 DELETE·POST(무료 한도 소모)도 가능. 프리플라이트에 `Access-Control-Allow-Private-Network: true`도 붙여 줌.
- **재현 2 (DNS 리바인딩)**: `curl -H "Host: evil.example:3000" http://127.0.0.1:3000/api/entries` → 200 + 전체 목록.
- **기대**: 이 컴퓨터의 일기장 화면 외에는 일기를 읽을 수 없음.
- **확인 범위**: 루프백의 다른 출처에서만 재현함. 공개 인터넷 사이트에서는 최신 Edge/Chrome의 로컬 네트워크 접근 권한 요청이 한 번 더 막을 수 있으나 확인하지 못함.
- **관련**: R3(비밀 보호 취지), R7(file:// 설계)
- **수정 방향(백엔드)**: ① `Host`가 `127.0.0.1:<port>`·`localhost:<port>`가 아니면 403. ② `null` 허용을 없애려면 file:// 화면이 서버 확인 후 `http://127.0.0.1:3000/`으로 이동(같은 출처)하도록 바꾸는 방안 — R7 설계와 관련되므로 `product-manager` 판단 필요. ③ 최소한 `Allow-Private-Network` 응답은 `null`에 주지 않기.

### B-03 위기 표현 감지 범위가 좁아 109 안내가 빠질 수 있음
- **심각도**: 높음 (안전 기능)
- **위치**: `src/diary.js:220` `CRISIS_PATTERN`
- **재현**: `detectCrisis()` 결과
  ```
  false I want to die
  false I want to end it all
  false 살 이유가 없어
  false 다 끝내고 싶다
  false 자고 일어나지 않았으면 좋겠어
  ```

4. **정규식만 잡은 경우(모델 false) 공감 문구가 109 문구와 따로 놉니다.** C02 "마음이 편해지셨다니 다행이에요 … 내일도 좋은 하루가 되시길 바라요. 혼자 견디기 힘드시다면 109…". 서버는 109만 덧붙이고 문구는 그대로 둡니다.
