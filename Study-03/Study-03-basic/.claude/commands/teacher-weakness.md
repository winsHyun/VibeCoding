학급 전체의 약점을 분석하고 보충 지도 계획을 제안해줘.

## 입력값
- 전체 입력: `$ARGUMENTS`
- `--period <기간>`이 있으면 떼어 내 기간으로 쓴다. 비어 있으면 `all`. 허용 값은 `.claude/commands/teacher-collect.md`의 "기간 값"을 따른다.
- 남은 값이 있으면 카테고리로 쓴다. (따옴표 제거. 예: `/teacher-weakness "예술과 문화"`) 비어 있으면 모든 카테고리를 분석한다.
- 카테고리가 `script.js`의 `CATEGORIES`에 없으면 실행하지 말고 사용할 수 있는 카테고리 목록을 보여준다.

## 준비
- `.claude/commands/teacher-collect.md`의 "공통 기준"을 읽고 그대로 따른다.
- `teacher-data/class-history.json`이 없으면 `/teacher-collect`를 먼저 실행하라고 안내하고 멈춘다.
- 문제 풀 현황은 `node`로 `questions.js`를 읽어(`eval(source + ';quizQuestions')`) 센다.

## 보여줄 내용
### 1. 학생 × 카테고리 정답률 표
| 학생 | 한국사 | 세계지리 | 과학 | 예술과 문화 | 평균 |
|------|--------|----------|------|-------------|------|
| **학급** | | | | | |

- 60% 미만은 🔴, 60~79%는 🟡, 80% 이상은 🟢를 앞에 붙인다. 표본이 적은 칸은 색을 붙이지 않고 "(표본 적음)"으로 적는다.
- 카테고리를 지정했으면 그 카테고리 열과 평균 열만 보여준다.

### 2. 카테고리 × 난이도 학급 정답률
| 카테고리 | easy | medium | hard | 플레이한 학생 수 |
|----------|------|--------|------|------------------|

- 난이도를 `all`로 플레이한 게임은 난이도별로 나눌 수 없어 여기서 빠진다는 점과, 빠진 게임 수를 표 아래에 적는다.

### 3. 약점 순위
학급 정답률이 낮은 카테고리(또는 카테고리·난이도)부터 최대 3개를 고르고, 각각에 대해 적는다.
- 학급 정답률과 전체 평균과의 차이
- 보충이 필요한 학생: 그 카테고리 정답률이 60% 미만인 학생 (표본 기준 충족한 학생만)
- 지도 제안: 해당 학생들에게 권할 모드·난이도 (예: "카테고리별 도전 · 과학 · easy를 3회")

### 4. 문제 풀 점검
약점 카테고리마다 `questions.js`의 난이도별 문제 수를 보여주고, 아래에 해당하면 보강을 제안한다.
- 난이도별 문제 수가 10개(카테고리별 도전 1회 분량, `GAME_MODES.category.questions`) 미만이면 학생들이 같은 문제를 반복해서 풀게 되므로 `/quiz-add <카테고리> <난이도>` 또는 `/quiz-daily`를 제안한다.
- 정답률이 매우 낮은데(40% 미만) easy 문제가 적으면 easy 문제 추가를 먼저 제안한다.

### 5. 분석의 한계
- 저장되는 기록에는 문제별 답안이 없어(`script.js`의 `endGame`이 `ScoreManager.summarize` 결과만 저장) **어떤 문제를 많이 틀렸는지는 알 수 없다**는 점을 적는다.
- 문항별 분석이 필요하면, `saveGameResult`에 넘기는 값에 `answers`의 `questionId`·`isCorrect`를 함께 저장하도록 코드를 바꾸는 방법을 한두 줄로 제안한다. 코드는 사용자가 요청할 때만 수정한다.

## 주의
- 이 명령은 보고만 한다. `questions.js`를 포함해 어떤 파일도 만들거나 수정하지 않는다. 문제 추가는 제안만 하고, 실행은 사용자가 한다.
- 계산에 쓴 임시 스크립트는 스크래치패드에 만든다.
