퀴즈 게임의 통계를 확인하고 관리해줘.

## 입력값
- 작업: `$0` (비어 있으면 `pool`)
- 파일 경로: `$1` (`play` 작업에서만 사용)
- 작업이 `pool`, `play`, `test` 중 하나가 아니면 실행하지 말고, 아래 "작업 목록"과 사용 예를 보여준 뒤 다시 입력해 달라고 안내한다.

## 작업 목록
| 작업 | 하는 일 | 예시 |
|------|---------|------|
| `pool` | `questions.js` 문제 풀 통계 | `/quiz-stats` |
| `play` | 브라우저에서 내보낸 플레이 기록 통계 | `/quiz-stats play history.json` |
| `test` | 통계 계산 로직(`LocalDataManager.getStats`) 점검 | `/quiz-stats test` |

## 참고: 통계 데이터 구조
- 플레이 기록은 브라우저 `localStorage`의 `gameHistory` 키에 배열로 저장된다. (최대 500개, `localDataManager.js` 참고)
- 기록 한 개의 주요 필드: `playerName`, `mode`(full/speed/category), `category`, `difficulty`(all/easy/medium/hard), `totalScore`, `correctAnswers`, `totalQuestions`, `accuracy`, `averageResponseTime`, `longestStreak`, `hintsUsed`, `categoryStats`, `timestamp`
- 브라우저 저장소는 직접 읽을 수 없으므로, 플레이 기록 통계는 사용자가 내보낸 JSON 파일로 계산한다.

## `pool`: 문제 풀 통계
`node`로 `questions.js`를 읽어(`eval(source + ';quizQuestions')`) 아래 표를 만든다.

1. 카테고리 × 난이도

| 카테고리 | easy | medium | hard | 합계 | 정답 위치 (1/2/3/4번) |
|----------|------|--------|------|------|------------------------|

2. 전체 정답 위치 분포 (위치별 개수와 비율)
3. 게임 모드별 실제 출제 가능 문제 수: `script.js`의 `GAME_MODES`와 `pickQuestions` 규칙(전체 도전은 카테고리마다 같은 수, 난이도 필터 적용)을 따라, 난이도(전체/쉬움/보통/어려움)마다 계산한다.

| 난이도 | 전체 도전 | 스피드 퀴즈 | 카테고리별 (한국사/세계지리/과학/예술과 문화) |
|--------|-----------|-------------|-----------------------------------------------|

4. 아래에 해당하면 ⚠️로 표시하고 개선 방법(추가할 카테고리·난이도, 보기 순서를 바꿀 ID)을 제안한다.
   - 카테고리 문제 수가 20개 미만
   - 카테고리 안에서 어떤 난이도가 0개이거나 50%를 넘음
   - 정답 위치가 한 곳에 40% 넘게 몰림
   - 난이도 필터를 적용했을 때 모드의 정해진 문제 수(전체 40, 스피드 20, 카테고리 10)를 못 채움

## `play`: 플레이 기록 통계
1. 파일 경로가 없거나 파일이 없으면, 브라우저에서 기록을 내보내는 방법을 안내하고 멈춘다.
   - 게임 페이지에서 개발자 도구(F12) → Console에 `copy(localStorage.getItem('gameHistory'))` 입력
   - 복사된 내용을 메모장에 붙여 넣어 `history.json`으로 저장한 뒤 `/quiz-stats play history.json` 실행
2. JSON을 읽고, 배열이 아니거나 필드가 빠진 기록은 건너뛰되 건너뛴 개수를 적는다.
3. 숫자가 앱과 똑같이 나오도록 **`localDataManager.js`의 `LocalDataManager`를 그대로 불러와** 계산한다. (메모리 저장소 객체에 파일 내용을 `gameHistory`로 넣고 `getStats`, `filterHistory`를 호출)
4. 아래 내용을 보여준다.
   - 전체 요약: 총 플레이 수, 플레이어 수, 기간(첫 기록 ~ 마지막 기록)
   - 플레이어별 표

| 플레이어 | 플레이 수 | 최고 점수 | 평균 정답률 | 누적 정답 | 마지막 플레이 |
|----------|-----------|-----------|-------------|-----------|---------------|

   - 모드·난이도별 표: 플레이 수, 평균 점수, 평균 정답률
   - 카테고리별 정답률 (전체 플레이어 합산): 정답률이 가장 낮은 카테고리를 표시
   - 추세: 플레이어마다 처음 5게임과 최근 5게임의 평균 정답률 비교 (5게임 미만이면 생략)
5. 이상한 기록이 있으면 따로 적는다. (점수가 음수, 정답 수가 문제 수보다 큼, `accuracy`가 정답 수/문제 수와 맞지 않음, 미래 시각 등)

## `test`: 통계 로직 점검
1. `node tests/localDataManager.test.js`를 실행하고 결과(통과/실패 개수, 실패 메시지)를 그대로 보여준다.
2. `localDataManager.js`의 `getStats`와 `script.js`의 `renderDashboard`·`endGame`을 읽고 아래를 확인한다.
   - 결과 화면(`ScoreManager.summarize`)과 저장되는 기록의 필드가 서로 맞는지
   - 평균 정답률이 게임별 정답률의 평균이 아니라 누적 정답 / 누적 문제 수로 계산되는지
   - 기록이 0개일 때 0으로 표시되는지 (`-Infinity`, `NaN`이 나오지 않는지)
3. 문제를 찾으면 원인 위치(`파일:줄`)와 수정 방법을 제안한다.

## 주의
- 이 명령은 점검과 보고만 한다. `questions.js`, 소스 코드, 사용자가 준 기록 파일을 수정하지 않는다. 수정은 사용자가 요청할 때만 한다.
- 계산에 쓴 임시 스크립트는 프로젝트 폴더가 아니라 스크래치패드에 만든다.
