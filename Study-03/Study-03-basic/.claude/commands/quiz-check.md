`questions.js`의 퀴즈 문제마다 `correctAnswer`가 가리키는 보기가 실제 정답인지 검증해줘.

## 검증 대상
- 입력값: `$ARGUMENTS`
- 입력값의 앞뒤 공백과 따옴표를 제거한 뒤 아래처럼 해석한다.
  - 비어 있으면 **전체 문제**를 검증한다.
  - `숫자-숫자` 형식(예: `41-80`)이면 그 범위의 `id`만 검증한다. 시작이 끝보다 크면 두 값을 바꾸고, 바꿨다는 사실을 맨 위에 적는다.
  - 그 밖의 값은 카테고리 이름으로 보고 `category` 값이 같은 문제만 검증한다.
  - 해당하는 문제가 없으면 검증하지 말고, 사용법(`/quiz-check`, `/quiz-check 과학`, `/quiz-check 41-80`)과 함께 실제 카테고리 목록과 최소·최대 ID를 보여준다.
- 범위는 배열 순서가 아니라 `id` 값으로 정한다.

## 1단계: 구조 검사 (스크립트로 확인)
`node`로 `questions.js`를 읽어 아래 항목을 기계적으로 검사한다. 파일이 전역 `const` 선언이므로 `eval(source + ';quizQuestions')` 방식으로 배열을 꺼낸다.
- 필수 필드(`id`, `category`, `difficulty`, `question`, `options`, `correctAnswer`, `explanation`)가 모두 있음
- `id`가 중복되지 않음 (중복은 범위와 상관없이 전체 파일 기준으로 확인)
- `difficulty`가 `easy`/`medium`/`hard` 중 하나
- `options`가 정확히 4개이고, 중복이나 빈 문자열이 없음
- `correctAnswer`가 0~3 사이의 정수
- 문제 문구가 기존 다른 문제와 같거나 거의 같음 (중복 문제 의심)

## 2단계: 정답 검증 (문제마다 직접 판단)
각 문제마다 다음을 확인한다.
1. **정답이 맞는가?** `options[correctAnswer]`가 문제의 정답과 일치하는지
2. **오답이 정말 틀렸는가?** 다른 보기 중에 해석에 따라 정답이 될 수 있는 것이 없는지
3. **해설이 정답과 맞는가?** `explanation`의 인물·연도·수치가 정답 보기와 맞고 사실과도 맞는지
4. **정답이 하나뿐인가?** (CLAUDE.md "퀴즈 문제 교차 검증 가이드라인")
   - 최상급 표현('가장', '최초', '최대' 등)에 측정 기준이 있는지
   - 바뀔 수 있는 정보(인구, 기록, 순위 등)에 시점이 있는지
   - 지리적·분류적 범위가 한정되어 있는지

### 교차 검증 규칙
- 확신할 수 없거나, 수치·연도가 들어 있거나, 시간이 지나 바뀌었을 수 있는 내용은 **WebSearch로 2개 이상의 출처**를 확인한다.
- 출처끼리 다르면 주류 학설이나 공신력 있는 기관(유엔, 국가 기관, 백과사전 등)을 기준으로 판단하고, 그 사실을 비고에 적는다.
- 웹 검색을 하지 않고 일반 지식으로 판단한 문제는 "지식 기반"으로 표시한다. 검색한 것처럼 적지 않는다.

## 출력 형식
1. 맨 위에 검증 범위와 검증한 문제 수를 적는다.
2. **구조 검사 결과:** 문제가 없으면 "구조 오류 없음" 한 줄로 적고, 있으면 표로 보여준다.

| ID | 항목 | 내용 |
|----|------|------|

3. **정답 검증 결과:** 판정이 ✅가 아닌 문제만 표로 보여준다. 모두 ✅이면 "모든 문제의 정답이 정확함"이라고 적는다.

| ID | 카테고리 | 문제 | 현재 정답 | 판정 | 근거 | 수정 제안 |
|----|----------|------|-----------|------|------|-----------|

- 판정: ❌ 정답 오류 / ⚠️ 정답이 여러 개일 수 있음 / 📝 해설 오류 / 🕒 시점 갱신 필요
- 근거: 확인한 출처 이름과, 웹 검색 여부("검색 2건" / "지식 기반")
- 수정 제안: 바꿀 `correctAnswer` 값, 고칠 문구, 추가할 기준 등을 구체적으로 적는다.

4. **교차 검증한 문제 목록:** 웹 검색으로 확인한 문제의 ID와 출처를 짧게 적는다.
5. **요약:** 검증한 문제 수, 판정별 개수, 웹 검색으로 확인한 문제 수

## 주의
- 이 명령은 점검만 한다. `questions.js`를 수정하지 말고, 수정은 사용자가 요청할 때만 한다.
- 문제가 많으면 카테고리 단위로 나눠 검증하되, 결과는 하나의 표로 합쳐서 보여준다.
