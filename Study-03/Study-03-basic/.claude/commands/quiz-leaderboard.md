퀴즈 게임의 순위 시스템을 확인하고 관리해줘.

## 입력값
- 작업: `$0` (비어 있으면 `rules`)
- 두 번째 값: `$1` (`show`, `remove`에서 기록 JSON 파일 경로)
- 세 번째 값: `$2` (`show`에서는 기간 `daily`/`weekly`/`allTime`, 비어 있으면 `allTime` / `remove`에서는 플레이어 이름)
- 띄어쓰기가 있는 플레이어 이름은 따옴표로 묶어 입력한다. (예: `/quiz-leaderboard remove history.json "김 민수"`)
- 작업이 아래 목록에 없거나 필요한 값이 빠졌으면 실행하지 말고, 작업 목록과 사용 예를 보여준 뒤 다시 입력해 달라고 안내한다.

## 작업 목록
| 작업 | 하는 일 | 예시 |
|------|---------|------|
| `rules` | 현재 코드의 순위 규칙 설명 | `/quiz-leaderboard` |
| `show` | 내보낸 기록으로 순위표 계산 | `/quiz-leaderboard show history.json weekly` |
| `test` | 순위 로직 테스트와 경계 상황 점검 | `/quiz-leaderboard test` |
| `remove` | 특정 플레이어 기록을 뺀 새 JSON과 복원 방법 제공 | `/quiz-leaderboard remove history.json 민수` |

## 참고: 데이터 위치
- 순위표는 따로 저장되지 않고, 브라우저 `localStorage`의 `gameHistory` 배열에서 매번 계산된다. (`localDataManager.js`의 `getLeaderboard`)
- 브라우저 저장소는 직접 읽을 수 없으므로, 사용자가 내보낸 JSON 파일을 사용한다. 파일이 없으면 아래 방법을 안내하고 멈춘다.
  - 게임 페이지에서 개발자 도구(F12) → Console에 `copy(localStorage.getItem('gameHistory'))` 입력
  - 복사된 내용을 `history.json`으로 저장

## `rules`: 순위 규칙 설명
`localDataManager.js`의 `getLeaderboard`, `compareRecords`, `periodStart`, `getRank`와 `script.js`의 `renderLeaderboard`를 **실제로 읽고** 현재 규칙을 정리한다. (아래는 작성 시점의 규칙이므로, 코드와 다르면 코드 기준으로 설명하고 달라진 점을 알린다.)
- 정렬: 점수 높은 순 → 정답률 높은 순 → 먼저 달성한 순
- 플레이어당 최고 기록 1개만 순위에 오르고, 상위 10명까지 표시
- 기간: 오늘(로컬 0시부터), 이번 주(월요일 0시부터), 전체
- 필터: 모드(전체 도전/스피드/카테고리별), 난이도
- 결과 화면 순위: 같은 모드·카테고리·난이도의 전체 기간 순위

규칙을 표로 정리한 뒤, 개선할 만한 점(예: 모드별 문제 수 차이로 점수 비교가 불공평한 경우)이 있으면 제안한다.

## `show`: 순위표 계산
1. 앱과 결과가 똑같도록 **`localDataManager.js`의 `LocalDataManager`를 그대로 불러와** 계산한다. 메모리 저장소 객체에 파일 내용을 `gameHistory`로 넣고 `getLeaderboard`를 호출한다.
2. 지정한 기간으로 아래 순위표를 모두 보여준다. 기록이 없는 순위표는 "기록 없음"으로 적는다.
   - 모든 모드
   - 전체 도전, 스피드 퀴즈
   - 카테고리별 (한국사, 세계지리, 과학, 예술과 문화)

| 순위 | 플레이어 | 점수 | 정답률 | 모드·난이도 | 달성 일시 |
|------|----------|------|--------|-------------|-----------|

3. 동점자(점수와 정답률이 같아 달성 시각으로 순위가 갈린 경우)가 있으면 따로 표시한다.
4. 이상한 기록(점수 음수, 정답 수 > 문제 수, `accuracy` 불일치, 미래 시각, `playerName` 없음)이 있으면 순위표 아래에 목록으로 적는다.

## `test`: 순위 로직 점검
1. `node tests/localDataManager.test.js`를 실행하고 결과를 그대로 보여준다.
2. 테스트가 다루지 않는 경계 상황을 스크래치패드의 임시 스크립트로 확인하고 결과를 표로 보여준다.
   - 자정·월요일 0시 직전과 직후 기록의 기간 포함 여부
   - 점수·정답률·시각이 모두 같은 기록
   - 플레이어 이름의 대소문자·앞뒤 공백 차이
   - 기록이 0개, 1개, 11명 이상일 때
3. 기대와 다른 결과가 있으면 원인 위치(`파일:줄`)와 수정 방법을 제안한다.

## `remove`: 플레이어 기록 정리
1. 원본 파일은 수정하지 않는다. 지정한 플레이어의 기록을 뺀 새 파일을 같은 폴더에 `<원본 이름>.cleaned.json`으로 만든다. 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 사용자에게 확인한다.
2. 플레이어 이름이 기록에 없으면 파일을 만들지 말고, 기록에 있는 플레이어 목록을 보여준다.
3. 삭제할 기록 수와, 정리 전후의 전체 순위 상위 10명을 비교해 보여준다.
4. 브라우저에 반영하는 방법을 안내한다. 반영은 사용자가 직접 한다.
   - Console에서 `localStorage.setItem('gameHistory', JSON.stringify(<새 파일 내용>))` 실행 후 새로고침
   - 또는 앱의 "내 기록 → 내 기록 초기화" 버튼 사용 (현재 닉네임의 기록만 삭제됨)

## 주의
- 소스 코드와 `questions.js`는 수정하지 않는다. 수정은 사용자가 요청할 때만 한다.
- `remove` 외의 작업은 파일을 만들거나 바꾸지 않는다. 임시 스크립트는 스크래치패드에 만든다.
