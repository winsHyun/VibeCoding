`questions.js`의 문제 풀을 점검하고, 부족한 곳에 새 문제를 추가한 뒤 백업하고 보고해줘.

## 입력값
- 추가할 문제 수: `$0`
- 앞뒤 공백과 따옴표를 제거한 뒤 사용한다. 비어 있으면 3으로 한다.
- 1~10 사이 정수가 아니면 실행하지 말고, 사용법(`/quiz-daily`, `/quiz-daily 5`)을 보여준 뒤 다시 입력해 달라고 안내한다.

## 진행 규칙 (모든 단계 공통)
- 아래 7단계를 **순서대로** 진행한다. 단계를 건너뛰거나 순서를 바꾸지 않는다.
- 각 단계는 "작업 → 검증" 순서로 진행하고, 검증 조건을 모두 통과해야 다음 단계로 넘어간다.
- 검증에 실패하면 **즉시 중단**하고, 뒤 단계는 실행하지 않는다. 이때 "실패 보고" 형식으로 보고한다.
- 실패한 시점에 `questions.js`가 이미 바뀌었다면, 4단계 시작 전에 만든 임시 사본으로 되돌린 뒤 되돌렸다는 사실을 보고에 적는다.
- 계산·검사에 쓰는 임시 스크립트와 임시 사본은 프로젝트 폴더가 아니라 스크래치패드에 만든다.
- `questions.js`에 문제를 추가하는 것과 6단계의 백업 파일 생성 외에는 어떤 파일도 수정하지 않는다.

## 1단계: 파일 구조 이해
- 작업
  - `questions.js`를 읽고 `quizQuestions` 배열의 선언 방식, 항목 형식(필드, 들여쓰기, 따옴표, 카테고리 주석)을 파악한다.
  - `script.js`의 `GAME_MODES`, `CATEGORIES`, `pickQuestions`, `getQuestionPool`을 읽고 문제가 어떻게 출제되는지 파악한다.
  - `.claude/commands/quiz-add.md`의 "문제 작성 규칙"과 "검증 가이드라인"을 읽는다. (3·4단계에서 그대로 따른다)
- 검증
  - `node --check questions.js` 통과
  - `node`로 `eval(source + ';quizQuestions')`를 실행해 배열을 꺼낼 수 있음
  - 모든 항목에 필수 필드(`id`, `category`, `difficulty`, `question`, `options`, `correctAnswer`, `explanation`)가 있음
  - `questions.js`의 `category` 값 목록과 `script.js`의 `CATEGORIES`가 일치함

## 2단계: 현재 문제 개수와 분포 확인
- 작업: 스크립트로 아래 값을 계산한다.
  - 전체 문제 수, 가장 큰 `id`
  - 카테고리 × 난이도 문제 수
  - 전체와 카테고리별 정답 위치(1/2/3/4번) 분포
- 검증
  - `id` 중복 없음
  - `difficulty`가 모두 `easy`/`medium`/`hard` 중 하나
  - `options`가 모두 4개이고, 중복이나 빈 문자열이 없음
  - `correctAnswer`가 모두 0~3 사이 정수
  - 카테고리 × 난이도 합계가 전체 문제 수와 같음

## 3단계: 카테고리별 부족한 부분 파악
- 작업
  - 카테고리 × 난이도마다 목표 개수(카테고리별 도전 모드의 문제 수, 현재 `GAME_MODES.category.questions` = 10)와 비교해 부족한 수를 구한다.
  - 아래 기준에 걸리는 곳도 함께 찾는다.
    - 카테고리 문제 수가 20개 미만
    - 카테고리 안에서 어떤 난이도가 0개이거나 50%를 넘음
    - 정답 위치가 한 곳에 40% 넘게 몰림
  - 부족한 수가 큰 순서로 정렬해, 추가할 문제 수만큼 (카테고리, 난이도) 칸을 고른다. 부족한 수가 같으면 문제 수가 적은 카테고리를 먼저 고르고, 한 칸에 몰리지 않게 가능한 한 서로 다른 칸으로 나눈다.
  - 모든 칸이 목표를 채웠다면, 문제 수가 가장 적은 칸부터 고른다.
- 검증
  - 고른 칸의 수가 추가할 문제 수와 같음
  - 고른 칸의 카테고리·난이도가 모두 1단계에서 확인한 목록 안에 있음

## 4단계: 새 문제 작성과 중복 체크
- 작업
  - 시작하기 전에 `questions.js`의 임시 사본을 스크래치패드에 만든다. (실패 시 되돌리기용)
  - 3단계에서 고른 칸마다 `quiz-add.md`의 규칙에 따라 문제를 1개씩 작성한다.
    - `id`는 가장 큰 `id` + 1부터 차례로 붙인다.
    - `correctAnswer`는 문제를 하나 추가할 때마다 정답 위치 분포를 다시 세어, 가장 적게 쓰인 위치에 둔다.
    - 정답과 해설의 사실은 WebSearch로 2개 이상의 출처를 확인한다. 출처끼리 다른 내용은 해설에서 빼거나 다른 주제를 고른다.
  - 중복을 체크한다.
    - 같은 카테고리의 기존 문제를 모두 읽고, 같은 내용을 묻는지 직접 판단한다. (문구만 바꾼 문제도 중복)
    - 스크립트로 공백·문장부호를 뺀 문제 문구를 비교해, 기존 문제나 이번에 새로 만든 문제끼리 같은 문구가 없는지 확인한다.
    - 정답 보기가 같은 카테고리 기존 문제의 정답과 같으면, 묻는 내용이 다른지 다시 확인한다.
- 검증
  - 모든 새 문제가 `quiz-add.md` 검증 가이드라인 4개 항목(정답 유일성, 최상급 기준, 시간·범위, 교차 검증)을 통과함
  - 중복 문제 없음. 중복이 나오면 다른 주제로 바꿔 다시 작성하고, 같은 칸에서 3번 연속 중복이 나오면 실패로 보고 중단한다.

## 5단계: 문제 추가와 형식 검증
- 작업: 새 문제를 `quizQuestions` 배열 맨 끝(`];` 바로 앞)에 추가한다. 앞 항목 뒤 쉼표, 들여쓰기 4칸, 큰따옴표를 기존 형식과 맞춘다.
- 검증 (하나라도 실패하면 임시 사본으로 되돌리고 중단)
  - `node --check questions.js` 통과
  - 2단계의 구조 검사를 다시 실행해 모두 통과
  - 전체 문제 수 = 추가 전 문제 수 + 추가한 문제 수
  - 기존 문제 내용이 바뀌지 않음. (임시 사본의 배열과 비교해, 추가 전 `id`의 항목이 모두 그대로인지 확인)

## 6단계: 전체 데이터 백업
- 작업
  - 프로젝트 폴더에 `backups/` 폴더가 없으면 만든다.
  - 추가가 끝난 `questions.js`를 `backups/questions-YYYYMMDD-HHmmss.js`로 복사한다. (시각은 실행 시점)
  - 같은 데이터를 `backups/questions-YYYYMMDD-HHmmss.json`으로도 저장한다. (`quizQuestions` 배열을 들여쓰기 2칸 JSON으로)
  - 플레이 기록(`localStorage`의 `gameHistory`)은 브라우저에만 있어 백업할 수 없다는 점을 보고에 적는다.
- 검증
  - 백업한 `.js` 파일이 `questions.js`와 바이트 단위로 같음
  - 백업한 `.json` 파일을 `JSON.parse`로 읽을 수 있고, 문제 수가 `questions.js`와 같음

## 7단계: 실행 결과 상세 보고
아래 순서로 보고한다.

1. 단계별 결과

| 단계 | 결과 | 내용 |
|------|------|------|
| 1. 구조 이해 | ✅ | |
| 2. 개수·분포 확인 | ✅ | |
| 3. 부족한 부분 파악 | ✅ | |
| 4. 작성·중복 체크 | ✅ | |
| 5. 추가·형식 검증 | ✅ | |
| 6. 백업 | ✅ | |

2. 추가 전후 카테고리 × 난이도 비교

| 카테고리 | easy (전→후) | medium (전→후) | hard (전→후) | 합계 (전→후) | 정답 위치 1/2/3/4번 (후) |
|----------|--------------|----------------|--------------|--------------|---------------------------|

3. 추가한 문제

| ID | 카테고리 | 난이도 | 문제 | 보기 | 정답 위치 | 정답 | 확인한 출처 |
|----|----------|--------|------|------|-----------|------|-------------|

4. 중복 체크 결과: 문제마다 비교한 비슷한 기존 문제 ID (없으면 "없음")와, 다시 작성한 횟수
5. 백업 파일 경로 2개
6. 남은 부족분: 아직 목표(10개)를 채우지 못한 카테고리 × 난이도와 부족한 수, 다음에 실행할 명령 제안 (예: `/quiz-daily 5`)

## 실패 보고 형식
검증에 실패하면 다른 보고 없이 아래만 보고한다.

| 항목 | 내용 |
|------|------|
| 실패한 단계 | 예: 5단계 추가·형식 검증 |
| 실패한 검증 조건 | 통과하지 못한 조건 |
| 오류 내용 | 오류 메시지 원문, 문제가 된 `id`·줄 번호 |
| 완료된 단계 | 실패 전까지 통과한 단계 |
| 파일 상태 | `questions.js` 변경 여부, 되돌렸는지, 백업 파일 생성 여부 |
| 해결 방법 | 사용자가 할 수 있는 조치 |
