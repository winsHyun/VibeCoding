`questions.js`에서 $1번부터 $2번까지의 문제를 검토하고, 난이도 분포와 정답 위치 분포를 확인해줘.

## 검토 대상
- 시작 ID: `$1`
- 끝 ID: `$2`
- 범위는 배열 순서가 아니라 각 문제의 `id` 값으로 정한다. (파일 안에서 ID가 순서대로 있지 않으므로 `id` 값으로 골라낸다.)
- 입력값 처리
  - 두 값 중 하나라도 비어 있거나 숫자가 아니면 검토하지 말고, 사용법(`/quiz-range 1 20`)과 `questions.js`의 최소·최대 ID를 보여준 뒤 다시 입력해 달라고 안내한다.
  - 시작 ID가 끝 ID보다 크면 두 값을 바꿔서 검토하고, 바꿨다는 사실을 맨 위에 적는다.
  - 범위 안에서 존재하지 않는 ID가 있으면 "없는 ID"로 따로 적는다.
  - 범위 안에 문제가 하나도 없으면 검토하지 말고, 존재하는 ID 범위를 알려준다.

## 1. 문제별 검토
아래 표로 보여준다.

| ID | 카테고리 | 난이도 | 문제 | 정답 위치 | 정답 | 난이도 적정성 | 비고 |
|----|----------|--------|------|-----------|------|---------------|------|

- **정답 위치:** `correctAnswer` 값을 1~4번 보기로 바꿔 적는다. (0 → 1번)
- **정답:** `options[correctAnswer]`의 문구를 적는다.
- **난이도 적정성:** 문제 내용을 보고 표시된 난이도가 적절한지 판단한다.
  - ✅ 적절 / ⬆️ 더 어려움 (상향 제안) / ⬇️ 더 쉬움 (하향 제안)
  - 판단 기준: easy = 상식 수준, medium = 관련 지식을 조금 알면 풀 수 있음, hard = 세부 연도·인물·개념을 정확히 알아야 함
  - 보기 중 오답이 너무 뻔해서 정답이 쉽게 드러나는지도 함께 본다.
- **비고:** 아래 문제가 있으면 적고, 없으면 "-"로 적는다.
  - `correctAnswer`가 `options` 범위를 벗어남
  - 보기 수가 4개가 아님, 같은 보기가 중복됨
  - `correctAnswer`가 가리키는 보기가 실제 정답과 다름 (의심스러우면 2개 이상의 출처로 교차 확인)
  - `explanation`의 내용이 정답과 맞지 않음

## 2. 난이도 분포
| 난이도 | 문제 수 | 비율 | ID 목록 |
|--------|---------|------|---------|
| easy | | | |
| medium | | | |
| hard | | | |

- 한 난이도가 50%를 넘거나 어떤 난이도가 0개이면 ⚠️로 표시하고, 어떤 문제의 난이도를 조정하면 좋을지 제안한다.
- 1번 표에서 난이도 조정을 제안한 문제가 있으면, 조정 후의 분포도 함께 적는다.

## 3. 정답 위치 분포
| 정답 위치 | 문제 수 | 비율 | ID 목록 |
|-----------|---------|------|---------|
| 1번 | | | |
| 2번 | | | |
| 3번 | | | |
| 4번 | | | |

- 이상적인 비율은 위치마다 약 25%이다. 아래 경우에 ⚠️로 표시한다.
  - 한 위치가 40%를 넘음
  - 정답이 한 번도 없는 위치가 있음 (검토 문제가 8개 이상일 때만)
  - ID 순서로 정렬했을 때 같은 정답 위치가 3번 이상 연속됨 (해당 ID를 적는다)
- 치우침이 있으면 어떤 문제의 보기 순서를 바꾸면 좋을지 구체적으로 제안한다. (예: "ID 21: 정답 H2O를 1번 → 3번으로 이동")

## 4. 요약
- 검토 범위와 실제 검토한 문제 수 (없는 ID가 있으면 함께 적음)
- 난이도 분포 한 줄 평가
- 정답 위치 분포 한 줄 평가
- 난이도 조정 제안 문제 수, 비고에 문제가 있는 문제 수

## 주의
- 이 명령은 점검만 한다. `questions.js`를 수정하지 말고, 수정은 사용자가 요청할 때만 한다.
